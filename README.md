# Масштабная битва 3D

Двухсторонняя симуляция сражения до 2 400 юнитов: пехота, лучники, стрелы и шесть полков в каждой армии.

Физическая модель одинакова для всех стратегий и включает:

- ограниченную скорость разворота и фронтальный сектор рукопашной атаки;
- столкновение тел без свободного прохождения сквозь вражеский строй;
- поддержку соседних рядов и угрозу с фланга или тыла;
- усталость от марша и боя, восстановление отдыхающего резерва;
- локальную мораль, бегство и распространение паники;
- физическую точку падения стрелы, включая возможность дружественного огня;
- одинаковую для всех армий индивидуальную готовность лучников к выстрелу;
- три приказа лучникам: огонь вразнобой, залп с человеческой задержкой
  реакции и прекращение огня;
- сосредоточение организованного огня на назначенном полку без распределения
  «персональных» целей между отдельными стрелками.

Ни одна стратегия не получает скрытого множителя урона, здоровья, скорости или
меткости: результат создают расположение, движение и локальные взаимодействия.

## Запуск

Откройте `start.bat`. Он запустит локальный сервер и откроет симулятор по адресу `http://127.0.0.1:43131`.

Для загрузки Three.js при первом запуске требуется интернет.

В панели доступны скорости `0,25×`, `0,5×`, `1×`, `2×`, `3×`, `5×`, `10×`
и `20×`. Высокие режимы увеличивают бюджет фиксированных физических шагов на
кадр, поэтому ускоряется сама симуляция, а не только анимация.

## Быстрая диагностика без графики

`run-diagnostics.bat` запускает матрицу стратегий в чистом CPU-режиме без WebGL и анимации.

Визуальный и диагностический режимы используют один модуль `Battle` из
`diagnostic.js`: правила движения, поиска целей, стрельбы, урона и командования
совпадают. Ускоренный режим пропускает только отрисовку и независимо считает
несколько полноценных боёв параллельно.

Пример отдельного испытания:

```powershell
node diagnostic.js --blue crowd --red offensive --trials 100 --units 150 --seed 42
```

Полная матрица:

```powershell
node diagnostic.js --matrix --trials 20 --units 150
```

По умолчанию испытания распределяются по всем доступным логическим процессорам через `worker_threads`. Число потоков можно ограничить:

```powershell
node diagnostic.js --matrix --trials 100 --units 150 --workers 8
```

Один бой остаётся последовательной детерминированной симуляцией. Параллелятся
независимые бои, поэтому одинаковые `--seed`, составы и стратегии дают одинаковую
статистику при любом количестве worker-потоков.

Доступные стратегии: `crowd`, `offensive`, `defensive`, `adaptive`, `neural`,
`ppo`, `commander_v3`, `commander_v4`. Старые модели сохранены для
A/B-сравнения, а веса до изменения стрельбы лежат в
`legacy-models/pre-fire-modes`.

`crowd` не получает общих приказов или построений: каждый полк самостоятельно
идёт к ближайшему противнику. Бегущие по морали юниты покидают бой, достигнув
края поля. PPO-командир после длительного отсутствия потерь переходит к
преследованию, чтобы оставшиеся полки и лучники не поддерживали бесконечную
дистанцию.
Флаг `--json` выводит машиночитаемую диагностику.

## Локальный нейрокомандир

Стратегия `neural` использует локальную сеть без сетевых запросов. Политика
`48 → 32 → 24 → 12` отдельно выбирает для каждого полка один из семи секторов и
один из пяти приказов: удержание, продвижение, штурм, резерв или фланг.

Для запуска многопоточного эволюционного обучения откройте
`train-commander.bat` или выполните:

```powershell
node train-commander.js --generations 10 --population 12 --battles 12 --workers 16
```

Тренер создаёт случайные размеры армий, расположения, seed, противников и стороны
поля. Полученные веса сохраняются в `trained-policy.js` и после перезагрузки
используются одновременно визуальным и headless-режимами.

### Гибридное обучение CPU + GPU

`train-gpu.bat` запускает цикл обучения, в котором CPU worker-потоки проигрывают
точные бои общим с визуальным режимом ядром, а PyTorch CUDA обучает политику на
собранных траекториях. Это сохраняет идентичную физику: на GPU переносится
обновление нейросети, а не упрощённая копия симулятора.

```powershell
train-gpu.bat
```

Сборщик `collect-rollouts.js` создаёт случайные размеры, расстановки, стороны и
противников. `gpu-train-commander.py` отбирает наиболее успешные решения,
обучает сеть пакетами на CUDA и после каждого цикла экспортирует совместимые с
браузером веса в `trained-policy.js`.

## PPO-командир с памятью

`ppo` — отдельный улучшенный вариант, не заменяющий старую сеть. Он использует
Actor–Critic: полносвязный кодировщик 48 → 64, GRU-память на 48 значений,
две policy-головы (7 секторов и 5 приказов) и value-голову. В модели 20 189
обучаемых параметров.

Траектории рассчитываются тем же CPU-ядром `Battle`, которое используется
визуальной симуляцией. Несколько боёв параллельно исполняются через
`worker_threads`, а обновления PPO считаются в PyTorch на GPU:

```bat
train-ppo-gpu.bat
```

Либо с ручными параметрами:

```powershell
.\.venv-gpu\Scripts\python.exe train-ppo-commander.py `
  --node "C:\Users\aleks_000\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe" `
  --cycles 8 --battles 192 --validation-battles 96 --workers 16
```

Каждый цикл собирает новые действия текущей политики, выполняет clipped PPO
обновления и проверяет кандидата на отдельном наборе случайных боёв. В
`trained-ppo-policy.js` экспортируется лучшая проверенная модель, а не просто
последняя. Чекпойнт сохраняется в `.training/ppo-best.pt`.

## Командир V3

`commander_v3` принимает совместное решение для всей армии. Каждый полк
кодируется общим encoder-слоем, self-attention обменивает информацию между
полками, общая GRU хранит историю боя, а централизованный critic оценивает
состояние всей армии. Модель содержит 49 645 параметров.

Архитектура не привязана к шести полкам: веса общие для всех regiment-токенов,
attention работает по маске активных токенов, а pooling нормализован по их
количеству. Поэтому будущие армии с разным числом пехотных и лучных полков не
потребуют менять размер сети. Для хорошего качества на новых составах их всё
равно нужно добавить в физический генератор и тренировочный curriculum.

Полное GPU-обучение:

```bat
train-commander-v3-gpu.bat
```

V3 использует full-sequence recurrent PPO с BPTT, зеркальные seed за обе
стороны, одинаковый вес эпизодов, KL early stopping, адаптивное исследование,
централизованный value loss и masked-token robustness loss. Лучший чекпойнт
выбирается только по отдельным боям против `crowd`.

## Командир V4

`commander_v4` — иерархический командир на 41 779 параметров. Encoder и
self-attention читают переменное число полков, GRU хранит ход боя, после чего
три policy-головы совместно выбирают:

- одну из восьми армейских доктрин;
- сектор сосредоточения;
- режим стрельбы лучного полка: `independent`, `volley` или `hold_fire`.

Перед PPO используется офлайн Monte Carlo-наставник: на случайных зеркальных
расстановках он перебирает совместные планы целиком и создаёт примеры для
предварительного обучения. Затем league PPO играет против толпы, V3, PPO,
старой нейросети и ручных тактик.

V4 также использует только наблюдаемую геометрию противника: компактный
неподвижный строй атакует сосредоточенно во фланг, а широкое наступление
встречает контратакой. Название стратегии соперника модели не передаётся;
урон, здоровье, скорость, мораль и точность остаются общими.

Итоговый независимый турнир после полного переобучения на новой стрельбе
(`280` новых боёв для каждой старшей модели):

| Модель | Победы | Поражения | Доля побед |
|---|---:|---:|---:|
| Commander V4 | 228 | 52 | 81,4% |
| Commander V3 | 213 | 67 | 76,1% |
| PPO | 160 | 120 | 57,1% |

V4 отдельно закончила серии против `crowd` со счётом `25–15`, против V3
`31–9`, против PPO `25–15`; ни один из 280 боёв не завершился таймаутом.

Запуск полного обучения V4:

```bat
train-commander-v4-gpu.bat
```

## Камера

- ЛКМ — вращение.
- ПКМ — панорамирование.
- Колесо — приближение.
- `WASD` — свободное перемещение.
- `Q` / `E` — вниз / вверх.
